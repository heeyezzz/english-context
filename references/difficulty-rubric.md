# 难度量规（大模型自评用，脚本不校验内容）

起草前画像、成稿后自评，都用这张表打分。四个维度各 1–3 档，整数。
有效量程只有 A2→B1——这是单人 i+1 私教，不是出版社分级体系。

## 打分表

| 维度 | 1 档（低负荷） | 2 档（常规） | 3 档（高负荷） |
|---|---|---|---|
| **vocab** 词汇 | 目标词全部来自当前 tier 词池的常见义 | 常规：tier 词池目标词 4–5 个 | 目标词触及 tier 上缘，或含熟词生义用法（如 run a store 的"经营"） |
| **syntax** 句式 | syntaxCalm 级别：单句 ≤16 词、平均 ≤10，简单句为主 | 常规：单句 ≤20、平均 ≤12，单层从句 | 硬闸上限内允许更多复合句：主谓被修饰语隔开、两句以上嵌套 |
| **discourse** 语篇 | 线性叙事，显性衔接（First/Then/Finally），代词紧跟前词 | 常规新闻结构：导语+展开+引语，标准书面衔接（However/Therefore） | 观点对比或转折递进，段落间靠语义过渡，指代距离拉长 |
| **background** 背景 | 兴趣列表内的熟悉话题 | 通识常识话题（不需要专业知识，但也不在兴趣列表） | 陌生话题：涉及新概念/新领域知识 |

## 三条使用规则

1. **事前写死**：predicted 在起草前定、送检前写进 meta.json，归档后不可改——先射箭后画靶作废。
2. **总负荷守恒**：四维之和常规 ≤8。background=3 时 vocab+syntax 必须压到合计 ≤3——
   把认知预算让给背景理解。画像最常见的样子是无聊的（2/2/2/1）。
3. **自评要对照校准历史**：pool 输出的 `calibration` 是过去的对账，有两条线——
   `predicted→requested` 看你的手估值不值钱（连续估偏同一维度同一方向，把该维锚点反向调），
   `requested→feel` 看这一篇交得合不合意。量规是死的，你的手是被校准的。

## 事前协商（v1.15.0）

画像定完后、动手写正文**之前**，把四维用**一句人话**讲给学习者听，等他点头或否决：

> 「今天这篇我打算：词略生、句子常规、衔接紧、话题熟。」

- 他否决或点菜 → 照他说的改，改完那份写 `meta.requested`。
- **你自己原来那份照写 `meta.predicted`** —— 两个字段都要写，一个都不能省。
  合成一个字段会让 `predicted` 不再是独立判断，两条校准线一起报废。
- 协商只动这四维。**不能动 tier**（词池是测量问题，归脚本闸门），**不能突破硬闸**（生词率、句长上限照旧）。
- 与 `syntaxCalm > 0` 冲突时（他要点"难"的句型，但上篇报了 dense）：**以 `syntaxCalm` 为准**。
  那是实际发生的受挫证据，点菜只是愿望——愿望不覆盖证据。

## 探针（v1.15.0）

一个只说 ok 的回路等于没有回路：14 篇 counted、体感 14/14 全是 ok、tier 一次没动过——
待在舒适区里的人当然报舒适，边界测不出来，只能探出来。

**触发**：`calibration` 里最近**连续 3 篇** predicted 四维之和 ≤7，且 feel 全为 `ok`。

**动作**：把**一个轴顶到最紧/最难档**（不是"顶一维到 3"——动作落在五轴参数上，见下节）。
轮转顺序 **语篇 → 背景 → 句法 → 词汇 → 题型**（语篇排第一：它完全没被控过，且不换词就能增减难度）。

**怎么读结果**：

- 被否 / 报 wordy・dense・context・choppy → 边界就在附近，退回来
- 报 ok / flow → 边界外移，**这是真正的升级信号**

**探针也要协商**：动手前告诉学习者「这篇我故意在 X 上加码」，他不想就跳过。
探针会真的改档位（`ledger.mjs axes`），所以更需要事前说清楚——这和"四维画像只记录"不是一回事。

## 五轴参数 vs 四维画像（v1.16.0）

**这是两套东西，别混。** 四维画像是你的**判断**（只记录），五轴档位是**参数**（真的改文章）：

| 四维画像（判断，只记录 1–3） | 对应的五轴档位（参数，真的生效） |
|---|---|
| `vocab` | **词汇 tier 1–8**（复合稀有度词池） |
| `syntax` | **句法 syntax 0–4**（句长 + 小句数 + 被动） |
| `discourse` | **语篇 cohesion 0–3**（衔接双向） |
| `background` | **背景 background 0–2**（选题兑现） |
| （无对应） | **题型 quiz 0–2**（推断题比例） |

画像仍然**不驱动**参数；但探针把"顶到最紧档"这个**动作**写在档位上，所以探针是两套东西的交汇点：
它用画像的观察结果，去动真参数。读当前档位：`pool`/`status` 的 `axes` 字段。

## 什么不归这张表管

词频、句长、小句数、被动、衔接、复现次数、超纲率是**测量问题**，永远归 passage-check 硬闸。
这张表打分再高，硬闸 FAIL 照样打回。判断归你，测量归脚本。
