# 无人值守点单（无人在对话里）

适用条件：请求由脚本或远端页面提交，**没有学习者在场**，四轴档位随请求一起到达。
本篇只描述与 `SKILL.md` 正常会话流程**不同的地方**；没提到的步骤（选词、配额、防重复、
归档锚定、曝光只在 confirm 计数）与正常会话完全一致，不在此重述，以 `SKILL.md` 为准。

**读这一份不是为了搞懂规矩后自己发挥。** 流程仍照 `SKILL.md` 走，本篇只覆盖"没人可问"时的差异。

## 一、档位视为已完成协商

面板不念、菜单不念、`history` 不念——那三步是给学习者做选择用的，此刻选择已经做完。

- 请求带来的四个数字用 `ledger.mjs axes --tier N --syntax N --cohesion N --background N`
  **原样落地，一个数字都不许改**。
- 不得因为"这篇读起来似乎太易/太难"自行调档。难度变动 100% 由学习者决定（v1.19.0），
  无人值守不是例外，是更容易出错的那一半。
- 档位数字超出 `pool` 菜单的合法范围 → 判为非法请求，直接失败返回，不要夹紧到最近的合法档。

## 二、主题

请求指定了主题就用它；若与 `pool` 的 `recent` 场景雷同，**保留主题换角度**（场景、人物、结局至少
换一项），不是换主题。未指定主题时取最久未用的兴趣，同样对照 `recent` 防重复。

## 三、失败要有回执，不许沉默

有人在场时你会说话；无人值守时**没人会知道你停在哪一步**，所以每一步的中止都要落成一条明确
回执，写清「失败」＋**具体项原文**（把 `fail` 数组原样带回去，不要转述成"校验未通过"）。

回执的具体形式由宿主项目提供（一条固定命令或一个固定文件），本 skill 不规定它长什么样。

## 四、硬性中止条件

| 情况 | 正确动作 | 被禁的動作 |
|---|---|---|
| `state-git pull` 报 `conflict` | 立即中止 + 回执"台账冲突，需人工决定哪台为准" | 自动合并、以本机为准硬 push |
| `passage-check` 第 4 次仍 FAIL | `ledger void --session <id>`（零记账，归档文件一并删除）→ 回执贴 `fail` 原文 | 降档凑数、删掉生词表再送检、手写绕过闸门 |
| Anki 端点连不上 | 沿用上次的 `anki-words.json`，重逢词据实少给或不给，**继续生成** | 因缺端点中止整篇 |
| `pool` 报 `saturated: true` | 不收新词，`mustReuse` 满配额即起草 | 为了"内容更丰富"仍掺入新词 |
| 请求缺任一档位数字 | 中止 + 回执"档位不全" | 用 `current` 补齐后当作学习者本人选定的 |

## 五、临时文件

一律 `T=$(mktemp -d)`，草稿、`meta.json`、`--report`、词级预查探针都写进 `$T/`。
固定路径（`/tmp/probe.md` 之类）在无人值守下会被旧文件覆盖检查挡住，或读到上一轮留下的旧草稿。

## 六、毕业与卡片

出现毕业候选时**不自动 `graduate`**，只把候选词写进回执。毕业会永久改动词的生命周期，
且下游的 Anki 桥接有自己的确认门（`SKILL.md` 第 9 步：只提出，永不自动导入）。

## 七、边界（无人值守专用）

agent 只做两件事：**按本篇与 `SKILL.md` 生成内容**，以及**调用宿主项目提供的固定交付命令**。

- 不自己拼部署/发布命令，不猜参数。写权限在无会话确认时等于没有门禁，一次参数写错就把半成品推到生产。
- 不修改 `~/.agents/skills` 下任何文件，不执行 `scripts/ship.mjs`。
- 不创建或修改任何定时任务。
- 不 `sudo`；除台账 `$STATE/`、宿主项目指定的输出目录、`$T/` 之外不写任何路径。
- 交付产物需要宿主项目定义的元数据块与占位符时，**照该项目现有文件的格式复制**，不要自创字段。
